# Contributing and evaluation

Start with the [reviewer guide](https://github.com/camiloavilacm/qa-features/blob/main/REVIEWER_GUIDE.md). This is a completed educational showcase; issues and proposed improvements are welcome, but there is no promise of ongoing feature development or production support.

Choose one automation framework to study. Run the documented checks and retain actual results. Do not change approved acceptance criteria to accommodate defects. Development-agent writes require explicit scope and the local governance procedure in `harness/README.md`; ordinary local test execution does not require harness activation. Never submit secrets, generated `.env` files, private operator keys, raw authentication traces, or local evidence directories.

Code is licensed under MIT; preserve third-party notices. Pull requests should explain behavior, validation, and limitations. Lightweight CI does not substitute for the full hosted acceptance campaign.

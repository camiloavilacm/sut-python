# Harness decisions

MASTER-CONTRACT.md remains the architectural authority. This file records implementation choices.

- Phase 0.5 is explicitly authorized by the user; Step 1 is not. Missing Phase 0 prerequisites do not prevent separately authorized preparation, but still block Step 1.
- Use Python stdlib plus pinned PyYAML and JSON Schema dependencies in an isolated environment. Development schemas are unrelated to business result/campaign schemas.
- JSON-compatible YAML configuration avoids ambiguous YAML scalar coercion while retaining YAML tooling.
- Claude imports AGENTS.md once through CLAUDE.md; mirrored skills are byte-identical generated copies.
- Native protocols remain separate. Antigravity uses camelCase and decision=deny; Claude uses snake_case and permissionDecision. Stop reporting does not force endless continuation.
- Codex relies on sandbox, execpolicy, preflight and final audit. No Codex lifecycle interception is claimed.
- Unknown tools fail closed. Claude shell effects require scoped human permission; Antigravity shell effects require external execution because a native headless ask decision did not block a fixture write. No universal shell parser is claimed.
- Product authorization is an external operator-controlled record, never generated by this harness. Recorder signatures use an external local key; same-principal malicious changes remain an external security concern.
- Read-only evaluations use isolated fixtures. Native parser validation is not project activation; a bounded session probe is not full native acceptance.
- Exported governance is deterministic, self-contained and stripped of authorization/ownership. Real repository propagation is deferred until each repository is authorized.

Known limitations and native acceptance blockers are maintained in planning/phase-05-report.md. No product repository, feature approval, tag or QA application code is created here.
